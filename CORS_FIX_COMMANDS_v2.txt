STEP 1: CHECK WHAT'S CURRENTLY SET
================================================

# Try .appspot.com first (usually correct for gsutil):

# If that gives BucketNotFoundException, try:

EXPECTED OUTPUT IF CORS IS SET:

  {
    "maxAgeSeconds": 3600,
    "method": ["GET", "POST", ...],
    "origin": ["http://localhost:5173", ...],
    ...
  }
]

IF YOU SEE [] OR NOTHING → CORS IS NOT SET!

STEP 5: CLEAR BROWSER CACHE (CRITICAL!)
================================================

Browsers cache CORS preflight responses!

Option 1 - Hard Refresh:
  • Open browser
  • Press Ctrl+Shift+R (3 times)

Option 2 - Clear Cache:
  • Press Ctrl+Shift+Delete
  • Select "All time"
  • Check "Cached images and files"
  • Click "Clear data"
  • Restart browser

Option 3 - Incognito Mode (Best for testing):
  • Open Incognito window (Ctrl+Shift+N)
  • Go to http://localhost:5173
  • Test there

================================================
TROUBLESHOOTING: STILL GETTING CORS ERROR?
================================================

Check which bucket Firebase is actually using:
1. Open browser console
2. Refresh page
3. Look for: "[Firebase] Storage bucket: codenest-63572.XXXXX"
4. Use THAT exact name in gsutil commands

Find which bucket actually exists:
gsutil ls -p codenest-63572

List contents of each bucket:
gsutil ls gs://codenest-63572.appspot.com
gsutil ls gs://codenest-63572.firebasestorage.app

Apply CORS to the one that DOESN'T give "BucketNotFoundException"

================================================
IF NOTHING WORKS - TEMPORARY TEST
================================================

Create cors-wildcard.json:
[
  {
    "origin": ["*"],
    "method": ["GET", "POST", "PUT", "DELETE", "HEAD"],
    "maxAgeSeconds": 3600
  }
]

Apply it:
gsutil cors set cors-wildcard.json gs://codenest-63572.appspot.com

Test upload. If it works, CORS was the issue.
Then revert to proper cors.json:
gsutil cors set cors.json gs://codenest-63572.appspot.com

⚠️ Don't leave "*" in production - security risk!
